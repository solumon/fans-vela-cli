# VELA 工时登记

使用项目提供的 `vela hours` 和当前 VELA CLI 会话。工时命令输出单行 JSON，以 `ok`、`submitted` 和 `error.code` 判断结果。遇到 `LOGIN_REQUIRED` 或 `SESSION_EXPIRED` 时，请用户在终端运行 `vela login` 并完成扫码，再继续原请求。CLI 不可用时，参考项目 README 的安装与构建步骤。

## 查询和准备

- 用 `vela hours day [--date YYYY-MM-DD]` 读取指定日卡片。用户没指定日期时，用命令返回的北京时间当天作为登记日期。预览和提交都传完整日期。有歧义的补登日期先问清。
- 用当天卡片解析项目名称。如果用户指定的项目不在当天卡片中，或要求查看可添加项目，用 `vela hours projects` 补查。名称先匹配全名，再匹配唯一片段；有多个候选时列出项目名称和 ID，让用户选定。
- 查询结果展示项目、是否已填、手填工时、待办自动工时、进度和工作内容，按请求选取相关列。直接采用 CLI 返回的当天合计。未填写或未知的字段显示为「—」。
- 新记录必须有 `hours`、`progress`、`content`。缺项时向用户补问。修改已填记录只传用户要求变更的字段，由 CLI 保留其他字段。用户只说「登记工时」时，先列当天卡片，再请用户提供项目及填写内容。不要把表单默认值或旧记录当作新记录的填写依据。

## 预览和提交

1. 把同一天要变更的项目组成 JSON 数组，每项包含实际 `projectId` 和填写字段。工时每项目 0.5–24 小时，按 0.5 小时递增，进度为 0–100 的整数，工作内容为 1–1000 字。使用 `vela hours submit --date YYYY-MM-DD --file -` 从标准输入传 JSON，或用 `--file` 传临时 JSON 文件。避免把用户提供的工作内容直接拼入 shell 命令。
2. 用预览结果列出日期、项目、操作、改动前后值。没有变更时直接说明。保留本轮预览的输入和 `previewId`。只有用户已经明确授权提交这组具体记录，或看过预览后明确确认提交，才用相同的日期和输入加 `--apply` 与该 `previewId`。用户修改内容时重新预览，并以其最新指令确定是否已授权提交。
3. 收到 `submitted: true` 后，用回查结果汇报日期、变更项目的手填工时、进度、工作内容和当天合计。待办自动工时单列。遇到 `PREVIEW_STALE` 时重新预览，展示变化后再取得提交确认。遇到 `SUBMIT_UNCERTAIN` 时先用 `day` 核对，说明实际看到的记录；不要自动重发提交。

该流程覆盖 VELA 本人单日查询、登记和修改。漏登检查、跨日批量提交和删除记录不在当前命令范围内。
