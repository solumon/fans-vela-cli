# VELA 开发任务应用关联

从任务详情链接的 `id` 或用户给出的任务编号定位任务。用当前 VELA CLI 会话执行 `vela task get <任务编号> --json`，按 `applications[].appId` 核对当前关联。用户只查应用时，提供当前关联和对应的目录候选。已有匹配关联时报告其版本和分支。所有目标应用都已有匹配关联时，返回现有关联 ID 供调用方使用。已有同应用的关联但字段不同，列出差异，由用户决定如何处理。

## 查找待关联应用

- 优先使用用户指定的应用名、ID 或仓库。没有指定应用时，从当前任务的需求、开发计划和相关工作区识别候选。根据 VELA 应用目录的名称、仓库地址和包路径核对。只有模糊匹配或多个同名时，列出各候选的名称与应用 ID，说明待核对的信息。
- 可用 `vela task app add <任务编号> --app <应用名> --json` 只读解析目录项。此时返回的默认分支 `dev` 仅用于查询。正式加入预览使用核实后的 `--app-id`、分支和版本。已知应用 ID 时可直接用 `--app-id` 查询。
- 优先使用用户指定的提测分支。其余情况从已核实的 Git 仓库和本次迭代的提交核对分支来源。用远端引用或已验证的远端提交确认分支，记录所用提交。共享仓库按应用核对包路径与分支。不要替用户把 CLI 默认的 `dev` 当作提测分支。
- 前端应用优先读取提测分支已核实提交中的应用 `package.json` 的 `version`，仓库根目录用 `git show <提交>:package.json`，多包仓库使用对应应用路径。用户明确指定版本时按指定值，若与包内版本冲突则在预览中标出。后端或无 `package.json` 的应用用当前构建或发行记录核实版本。任务曾关联过的版本、分支名中的版本号以及本地未提交文件都不能代替本次证据。确实缺少依据时，列出具体字段和需要确认的信息。

## 预览、确认和回查

1. 为每个参数已核实的应用执行 `vela task app add <任务编号> --app-id <应用ID> --branch <提测分支> --version <版本> --json`。用户明确同意让 VELA 处理未指定版本时可省略 `--version`。核对 `submitted: false` 和 `taskApp` 中的任务 ID、应用 ID、版本与分支，保留 `previewId`。一次显示各候选的应用名、ID、版本、分支和版本来源，列明哪些可确认加入，哪些还需核对。
2. 用户确认这次加入预览后，回查任务。如果关联已存在，比较其字段并报告实际状态。如果 Git 分支自预览后有变化，先核对当前提交的任务归属和版本。拟加入的参数变化时重新预览并确认。逐个用预览时的参数加 `--apply <previewId>` 提交用户确认的应用。
3. 核对 `submitted: true` 及返回的 `association`。如果收到 `APP_ALREADY_LINKED` 或 `SUBMIT_UNCERTAIN`，先回查 `vela task get <任务编号> --json`，按应用 ID、提测分支和已指定的版本核对实际关联及关联 ID。`PREVIEW_STALE` 时重新查询并预览。按应用报告已加入并核实、已有匹配关联或未能加入及原因。
4. 被更新内容技能调用时，将已核实的关联 ID、应用 ID、版本和提测分支交回调用方。加入确认仅授权关联操作，更新正文使用单独的预览和确认。

命令不可用时查 `vela task app --help`。会话明确失效时请用户执行 `vela login` 扫码。
